Chapter 02.3 · Target architecture

Optional acceleration without a second math contract.

Planning, reference CPU routing, selection policy, ordered REST batches, and guarded CUDA and Apple Metal foundations are implemented; exact native kernels and UDP remain targets. CPU stays the exact reference and HTTP stays the default transport.

Current status

java-api contains the immutable model and lazy provider SPI. Every equation routes through the execution planner and reference CPU backend. The REST service submits ordered cache misses as a batch. The independently optional CUDA and Metal artifacts guard JNI/device initialization and have deterministic non-hardware conformance fixtures, but advertise no executable operations until exact kernels pass their respective hardware gates. The discovery-only math2_metal bridge has opened and released the default Apple M3 Pro device in an explicit hardware test. There is no CUDA bridge, device buffer pool, conforming CUDA or Metal kernel, calculation hardware evidence, or UDP listener yet.

The configured modes are DISABLED, DETECT, and ENABLED. Disabled is the default and performs no provider discovery or native loading. Detection considers suitable accelerated providers in deterministic ID order and falls back to CPU if none can execute the complete plan. Enabled may use a conforming CUDA or Metal provider and never silently falls back. Docker is not a runtime prerequisite.

CUDA and Metal peers

CUDA targets compatible NVIDIA devices. The Metal artifact is the native alternative for Metal-capable macOS laptops, including Apple GPU systems where CUDA is unavailable. Both sit behind the same service-provider boundary; installing one does not make the core or REST service depend on its vendor SDK.

Exactness before speed

For the same engine version, equation, significant-digit precision, and rounding configuration, a backend must return the byte-for-byte CPU canonical decimal string. Native float/double arithmetic and tolerance-based comparisons cannot implement Math2 values. CUDA and Metal capabilities are advertised operation by operation only after the unchanged shared conformance suite passes on declared hardware.

Ordered batches

The planner can schedule a REST batch as one unit to amortize transfer and launch costs. Each equation keeps its input index, limits are checked before allocation, and results are restored to request order regardless of kernel completion order. Required-GPU mode rejects an unsupported batch before any item executes.

Optional UDP adapter

flowchart LR
 HTTP[HTTP · default] --> APP[Shared calculation service]
 UDP[UDP · opt-in] --> APP
 APP --> PLAN[Limits, planning, execution, cache]

UDP avoids a connection handshake but does not supply delivery, ordering, peer identity, encryption, integrity, or congestion control. The target listener is disabled by default, binds to 127.0.0.1:8081, limits datagrams to 1,200 bytes by default, and uses versioned JSON with a 128-bit request ID. Bounded replay handling makes exact-byte retries safe; oversized responses direct clients to HTTP.

Network safety

Plain UDP is for loopback or deliberately trusted local networks. Remote production access should continue to use HTTP behind authenticated TLS unless an authenticated datagram envelope is separately specified. Request, queue, replay, response-amplification, memory, and execution limits apply before work begins.

Verification gates

  • Normal CI passes with no GPU, native bridge, driver, vendor SDK, or Docker.
  • The pinned CUDA simulator environment provides an additional no-hardware kernel lane but does not test Metal or physical hardware.
  • The same backend suite compares exact CPU/CUDA and CPU/Metal strings across operations, precision, rounding, failures, and batches.
  • CUDA and Metal release evidence comes from their respective declared hardware, reports every skip, and remains separate.
  • Real loopback datagrams verify UDP single, batch, retry/replay, malformed, oversize, and disabled cases.
  • Existing live HTTP client verification remains required.

The complete design, SPI, decimal representation, failure policy, test matrix, and phased roadmap are in GPU and execution-backend architecture. Normative behavior is in REG-009 and REG-010.
