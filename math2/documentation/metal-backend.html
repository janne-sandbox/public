Chapter 02.4 · macOS acceleration

Metal is the native macOS GPU path.

The optional Java provider and discovery-only native bridge are implemented without making Docker, CUDA, Metal, or a GPU a core dependency. Device buffers and exact compute kernels are still pending.

Exact implementation boundary

java-metal-backend registers a lazy provider, validates immutable device metadata, owns an idempotent runtime lifecycle, and supplies deterministic no-hardware tests. build-metal-native.sh compiles the discovery-only math2_metal JNI library; an explicit test opened and released the default Apple M3 Pro device. Production capabilities are deliberately empty. There is no Metal compute kernel, device buffer pool, or calculation conformance evidence yet.

Selection behavior

ModeMetal behavior
DISABLEDUses CPU and does not discover the provider, load JNI, or probe a device.
DETECTMay initialize Metal only for a sufficiently large plan. An unavailable or unsupported foundation provider is closed and CPU executes.
ENABLEDConsiders every installed accelerated provider in deterministic ID order and fails closed if neither CUDA nor Metal supports the complete plan.

Build and explicit device verification

The Java foundation and macOS bridge build independently. The hardware test is intentionally outside normal Surefire patterns so ordinary CI neither requires Metal nor reports a hidden skip:

mvn -pl java-metal-backend -am test -Ddebug=false
./build-metal-native.sh
mvn -pl java-metal-backend -am \
  -Dtest=MetalHardwareIT \
  -Dsurefire.failIfNoSpecifiedTests=false \
  -DargLine=-Djava.library.path="$PWD/java-metal-backend/target/native" \
  test -Ddebug=false

The REST service has no direct dependency on this artifact. A macOS deployment must install the provider JAR together with the matching libmath2_metal.dylib and configure its native-library search path. Merely placing the JAR on the classpath does not load native code in the default disabled mode.

Numerical contract

Metal is not an approximate mode. Kernels must operate on Math2's bounded integer-limb representation, preserve configured precision and all rounding modes, retain batch order, and return the exact canonical CPU string. Shader-native floating-point and tolerance comparisons cannot implement calculation values.

Required evidence before operations are enabled

  • A bounded native bridge and buffer lifecycle, including cleanup on failure and cancellation.
  • Exact CPU/Metal parity for every advertised operation, precision, rounding mode, error, and ordered batch.
  • Declared macOS, Apple chip/GPU, Metal runtime, backend version, command, counts, failures, and skips.
  • Separate performance evidence; speed cannot relax correctness.
