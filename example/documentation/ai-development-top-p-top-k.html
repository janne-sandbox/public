AI DEVELOPMENT / Top-p and top-k

Two more sampling controls

After a language model assigns probabilities to candidate next tokens, the runtime can apply additional filters before sampling. Top-p and top-k are two common filters. They work alongside temperature — temperature reshapes the distribution; top-p and top-k then limit which tokens are eligible for selection.

ParameterWhat it doesCommon default
Top-kKeeps only the k highest-probability tokens as candidates. All others are excluded from sampling regardless of their probability.Provider-specific; often 40–50 or disabled (k = all).
Top-p (nucleus sampling)Keeps the smallest set of tokens whose cumulative probability meets or exceeds p. The cutoff shifts dynamically: it admits many tokens when the distribution is flat, and very few when one token is highly dominant.Often 0.9 or 1.0 (disabled).
Temperature, top-p, and top-k are complementary, not interchangeable. They are often applied together: temperature first reshapes the distribution, then top-k caps the candidate count, then top-p prunes to a cumulative probability threshold.

Top-k in detail

With top-k = 10, only the 10 most probable tokens remain eligible. The model will never produce any other token at that position, even one with a small but non-zero probability.

Top-k valueEffectWhen to consider it
Low (e.g., 1–5)Very narrow output; highest-probability tokens almost always chosen.Deterministic code snippets, format-constrained extraction.
Moderate (e.g., 20–50)Allows a small vocabulary of plausible alternatives.General code generation, documentation.
High / disabledNo hard vocabulary cap; relies on temperature and top-p instead.Creative tasks, open-ended brainstorming.

Setting top-k = 1 is equivalent to greedy decoding: the single most probable token is always selected. This is maximally deterministic but can cause repetitive output in longer generations.

Top-p (nucleus sampling) in detail

With top-p = 0.9, the model ranks all tokens by descending probability and keeps adding them to a candidate set until the cumulative probability reaches 0.9. The rest are excluded. Sampling then picks uniformly from the remaining candidates.

Top-p valueEffectWhen to consider it
Low (e.g., 0.1–0.5)Only the highest-confidence tokens are considered; output is focused and repeatable.Security review, classification, precise edits.
Moderate (e.g., 0.7–0.9)Admits alternatives when the distribution is flat; prunes rare tokens when a clear winner exists.Implementation drafts, documentation, chat.
1.0 (disabled)All tokens are eligible; filtering is handled by temperature and top-k only.When you want the other controls to operate without a probability cap.

The practical advantage of top-p over top-k is that the candidate set size adapts to the model's confidence: a highly confident prediction produces a small set; an ambiguous position produces a larger one. This makes top-p more portable across different tasks without re-tuning a fixed count.

How the three controls interact

A typical sampling pipeline applies the parameters in this order:

  1. Temperature — scales the raw logits, making the distribution sharper (low) or flatter (high).
  2. Top-k — removes all tokens outside the top k by probability.
  3. Top-p — further removes tokens outside the nucleus of cumulative probability p.
  4. Sample — draws one token from the remaining candidates.
Providers vary. Not every API or local runtime applies these filters in the same order, supports all three, or uses the same defaults. A parameter accepted by one endpoint may be silently ignored or rejected by another. Consult the specific model's current API schema.

Ollama example

Both parameters can be set in an Ollama Modelfile:

FROM llama3.2:3b PARAMETER temperature 0.3 PARAMETER top_p 0.85 PARAMETER top_k 30 SYSTEM You are a precise code reviewer.

Save it as Modelfile.review, then build and run:

ollama create precise-reviewer -f Modelfile.review ollama run precise-reviewer

Ollama uses the parameter names top_p and top_k; other APIs may use camelCase or different keys. Verify the accepted parameter names in the target runtime's current documentation.

What these controls do not do

Top-p and top-k do not add knowledge, reasoning, or accuracy. They influence token selection at generation time. They cannot fix a poorly scoped prompt, recover missing context, eliminate hallucination, or prove generated code is correct. Strong prompts, accurate context, grounding, tools, tests, and human review remain the most important factors in output quality.
